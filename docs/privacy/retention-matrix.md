Additional processors are OpenAI for selected AI/OCR tasks, eKasa for receipt QR lookup and Resend when email is configured. Provider-side retention/training settings and contractual transfer terms are **operator/legal verification items**; the repository cannot establish their current account settings. Original voice audio is not intentionally retained in application Storage. Inactivity or subscription termination does not trigger account erasure.

## Backup/erasure safety gate

The application keeps only a minimal database tombstone after fulfillment; a backup made before that event can still contain the old user. The daily backup now prepares a separate checksummed S3 ledger containing only request/user UUIDs, status and timestamps. The database will not claim an irreversible erasure until the backup and ledger are uploaded and verified. A restored database is checked against the newest independent ledger; a missing/stale ledger, missing request, revived completed user, or lost access revocation fails closed. Pending erasures still require replay before **live** promotion. The automated restore test is isolated and is not a live-promotion workflow. Never promote an older backup without comparing it with the newest S3 ledger and completing any pending erasures. This gate is prepared in code but not operational until the migration and first new backup run are verified in production.
